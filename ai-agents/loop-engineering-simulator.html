Loop engineering, running live

You're not designing prompts here — you're designing the while loop around the model: how it acts, observes, verifies, recovers, and knows when to stop. Pick a scenario and run it.

The return edge is the whole idea

Prompt engineering ends at the first answer. Loop engineering feeds the result of the action — test output, errors, API responses — back into the model's context and goes around again.

prompt engineering → context engineering → harness engineering → loop engineering

Each layer wraps the previous. The loop layer decides how the system observes, verifies, and recovers — the parts that only matter once things go wrong mid-execution.

01 · VERIFY

External validation

Success is decided by tests, compilers, or checks outside the agent — never by the agent's own judgment. Run the third scenario to see why.

02 · TERMINATE

Stopping conditions

Goal met, max iterations, or budget ceiling — whichever comes first. A loop without a stop condition is an incident, not an agent.

03 · RECOVER

Failure as input

Error traces and diffs flow back into context so each iteration is smarter than the last. Recovery paths are where the engineering effort actually goes.

04 · GOVERN

Budgets and breakers

Token ceilings, run logs, drift detection. This is what a bank audits — and where most enterprise loops are weakest.
